Typing faster than the server

A search box fetches results in an effect every time the query changes. If an earlier request answers after a later one, an effect without cleanup stores the earlier answer last and the page shows results for a query the user has already replaced. An effect with cleanup ignores answers for queries that are no longer current. Both components below get the same keystrokes and the server gives both the same delays, so any difference comes from the code. New to these terms? Start here.

The bug needs only one thing: an answer that takes longer than the time to the next keystroke plus the
    next answer. That depends on jitter and typing speed, and one user on a poor connection is enough. Search, list-to-detail panes,
    tabs, filters, pagination, route parameters and sliders all change an effect's input quickly. The fix is three lines.
