How rare is the race?

The race in Typing faster than the server depends on latency jitter compared with how fast the input changes. Traffic and server speed do not enter into it. This page types two characters into both search components many times, with real requests, and counts how often each one ends on stale results. Then it multiplies the measured rate by interactions per day. New to these terms? Start here.

The race is a scale problem: on steady networks it is close to nonexistent, and on mobile networks a few percent of quick searches end on the wrong results. Users rarely report it, because the results look plausible and they type again. Two things do not shrink with scale. The cost of one occurrence: a detail pane whose header says customer B while the form holds customer A's data, and a save that writes A's data to B. And the bugs in Switching users and The order placed twice, which happen every time. For your own app, compare the p95 and p99 latency of the endpoint with how fast its input changes.
