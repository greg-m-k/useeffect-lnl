Switching users

An editor keeps a draft of the selected user's name. When a different user is selected, the draft has to start again. Resetting it in an effect lets React render and commit the new user with the old draft first, then fixes it. Resetting it with a key starts a fresh editor in the same render. This bug needs no slow network and no bad luck: count the commits each time you switch. New to these terms? Start here.

Pick a user

Try: switch a few times by clicking, then turn on "Switch when data arrives" and switch again. Predict each time: how many commits show the wrong draft, and how many of those reach the screen?

The stale commit happens on every switch. Whether the browser also paints it depends on when React
    runs the effect relative to the next frame, which changes with what caused the switch; the counts above are what your browser did.
    Either way, anything that runs on commit or reads the DOM in that moment sees one user's name with another user's draft, including
    effects that send requests. Values that follow from props belong in render, and a reset belongs in a key.
