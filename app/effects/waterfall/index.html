Fetch, render, fetch again

A customer page needs the customer and their orders, and both requests need only the customer id. Effects in each component fetch the customer, render the orders list, and only then does the list's own effect fetch the orders. Fetching together starts both requests at once. The server answers each after the delay you set, and the timelines show when each request really started and finished. New to these terms? Start here.

Ready

Each level of nesting adds a full round trip, so the gap grows with latency and with depth. One user on
    a slow connection feels it on every page load, whatever the server's load. Route loaders, data libraries and server components exist
    largely to start these requests together, before the components that need them render.
